## Use Translation Keys for User-Facing Text

**Impact: HIGH (ensures all UI text is localizable and consistent with locale files)**

Every user-facing string (labels, buttons, messages, placeholders, titles) must go through the i18n layer. Use translation keys with `t()` or `i18n.t()` instead of hardcoded literals so that content can be translated and kept in `public/assets/locales/{{lng}}/{{ns}}.json`.

**Incorrect (hardcoded literals):**

```tsx
function SubmitButton() {
  return <button>Submit</button>
}

function Greeting() {
  return <h1>Welcome back</h1>
}
```

**Correct (translation keys):**

```tsx
function SubmitButton() {
  const { t } = useTranslation()
  return <button>{t("common.submit")}</button>
}

function Greeting() {
  const { t } = useTranslation()
  return <h1>{t("greeting.welcomeBack")}</h1>
}
```

Add the corresponding keys to the locale **source** (TypeScript in `packages/blocks/src/locales/` for block UI, or the app’s locale modules e.g. `apps/web/locales/` for app-only keys). The files under `public/assets/locales/` are generated by the merge-locales plugin—do not edit them by hand. Use a consistent key structure (e.g. by feature: layout, shared, or domains).

### No magic numbers in locale strings — use interpolation

Dynamic values (limits, counts, thresholds) must never be hardcoded in locale strings. Use i18n interpolation (`{{placeholder}}`) and pass the actual values from code constants at call site. This keeps the constants as the single source of truth and prevents locale strings from drifting out of sync when limits change.

**Incorrect (hardcoded numbers in locale strings):**

```ts
// locale file — numbers baked into the string
export default {
  "validation.minLength": "Must be at least 5 characters",
  "validation.maxLength": "Must not exceed 255 characters",
}

// component — no way to keep the number in sync with code
<p>{t("validation.minLength")}</p>
```

**Correct (interpolation with constants from code):**

```ts
// locale file — uses {{placeholder}} for dynamic values
export default {
  "validation.minLength": "Must be at least {{min}} characters",
  "validation.maxLength": "Must not exceed {{max}} characters",
}

// component — passes actual values from constants
<p>{t("validation.minLength", { min: LIMITS.MIN_LENGTH })}</p>
```

When a validation function needs to return both a key and interpolation params (e.g. for form error messages), use a structured error object instead of a plain string:

```ts
// validation function — returns key + params from constants
const error = {
  key: "validation.minLength",
  params: { min: LIMITS.MIN_LENGTH },
}

// component — destructures and passes to t()
<p>{t(error.key, error.params)}</p>
```
